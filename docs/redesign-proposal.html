How to read this

  • The doc runs Overview → Screens → Foundations → Decisions. Screens come in the order you meet them: Home, Add, Activity, Breakdown, Accounts, Import, then the rest.
  • Every phone has an ID (H1, AV3…) so feedback can point at it. Prefixes: H Home · A–G Add · AV Activity · BD Breakdown · AC/AB Accounts · I Import · R, T, S, O the other screens.
  • 1 numbered pins link taps to the table beside them. An orange ring marks what the user taps next.
  • A grey Today: line under a phone says what it replaces in the current app.
  • Decisions are collected in one place, Decided, numbered D1–D15. Each screen links to its own.
  • Hide balances, My setup and Theme (top right) switch every phone at once.
Overview · Principles

Five rules every screen must follow

When two options are on the table, these decide it. Most of today's inconsistency comes from screens being copied and tweaked one at a time, with no shared rule to check against.

01

One way to do each thing

One Add button, one add/edit form, one transaction list, one review queue, one import.

02

Same thing, same look

Every amount, row, header, card and button comes from one shared component. Screens may not restyle them.

03

Plain words

No "classify", "off-books", "LLM", "enriched" or "AI disagrees". Write it the way you'd say it to a friend.

04

Nothing lost silently

Every delete offers Undo. Every bulk or irreversible action asks first. Every form keeps a draft until you save or discard it.

05

Ask when it's needed

Permissions, AI keys and advanced filters are asked for at the moment they matter, not up front in onboarding.

The rules

  • Quick = amount, name, account, category, Save. Full = all fields in one fixed order. Rows can hide but never move.
  • Quick → Full: "More details", or any field Quick doesn't show. Full → Quick: tap the amount. Input always survives.
  • Opens in Quick from + and the Add widget. Everything that arrives with context (paste, tab actions, settle, edit) opens in Full.
  • Tabs live in two rows: "Paid from → Someone else" (they paid) and "For → a tab" (you paid for them, all of it). A partial share goes through Split.
  • Header = what you're doing. Save = what will happen. At most one context note, and only when the effect isn't obvious.
  • One picker sheet for account, category, tab, date and time.

Decided for Add

One form with two levels, name in Quick, no +100 chips, Split while adding, one default account, and guesses from the message before any default: D3–D8.

Screens · Import

Import: keep it, but make the review about exceptions

Are we keeping it? Yes, with a smaller review (D15)

SMS only covers what arrives from now on. Import is the only way to backfill history, cover cards and banks that don't text, and fix gaps when SMS was off. That's worth keeping.

What isn't worth keeping is making you review every row. The matching logic already sorts rows by confidence. So:

  • New (no match) → imported automatically, with categories guessed.
  • Already in Rupiyah (high confidence, including split matches) → not imported again. The bank's reference and description are added to your entry.
  • Need a look (medium confidence) → the only rows you're asked about.

Forms & leaving

  • Toggles save instantly. Text settings save on leaving, with no Save buttons on settings pages.
  • Add, Edit, Split, Transfer: back or swipe with unsaved input asks "Discard changes?" (today only Edit does).

Taps do one predictable thing

  • Tapping a transaction always opens its detail. Today, an uncategorized one opens a sheet instead.

  • Sort and search are visible icons, not hidden in ⋮.

  • Every chip does something (today "None" does nothing).

Decisions · Decided

Everything decided so far

Every choice made during review, in one list. The screens above already show them. D-numbers are only for referring to a decision; they're separate from phone IDs like H1 or A2.

Home

  1. D1Keep today's order: To review → Balance (with this month's net change) → This month by category or account → Open tabs.
  2. D2No recent transactions on Home. Activity is one tap away.

Add

  1. D3One form with a Quick level and a Full level, used for add, edit, settle and paste.
  2. D4Quick shows the name field (A1, A2, B3).
  3. D5The +100 / +500 / +1,000 chips are dropped.
  4. D6"Split into parts" is available while adding, not only on saved transactions.
  5. D7One default account, set in Accounts and shown there as a "Default" tag. Last-used is dropped.
  6. D8Guessing the account and category from the SMS or pasted text matters more than any default. The default is only the fallback when a message names no account.

Activity & Breakdown

  1. D9Keep grouping by month, with signed month totals. Day and time move into each row.
  2. D10All time by default: the first 50, then infinite scroll, also when filtered. No silent "This month".
  3. D11Period options: Today, This week, This month, Custom.
  4. D12Sort by time or amount only; the name sorts are removed.
  5. D13No "vs last month" for now.
  6. D14Monthly Exchange stays (you use it), simplified to one switcher, and is renamed Breakdown. This was open question 3.

Import

  1. D15Import stays: it's the only way to backfill history and cover accounts that don't text. Its review shows only the rows the matcher is unsure about.

Decisions · Order of work

Order of work

Building blocks come first, so every later step is mostly swapping old pieces for shared ones rather than redesigning. Each phase can ship on its own.

1

Foundation (no visible flow changes)

Add spacing, corner and money tokens and the ~8 components above. Delete ~1,400 lines of dead UI. Fix the three real bugs: the silent "Cash" save, hide balances, and the notification channel reset.

2

Add flow

One Add/Edit form with Quick and Full levels: Spent / Received / Transfer, Paste, "Paid from → Someone else" and "For", and Split while adding. + opens it directly. Drafts and Discard prompt.

3

Activity as the hub

Filtered Activity replaces Account and Category detail. Visible sort, select and period chip; All time by default with infinite scroll. Breakdown rows open filtered Activity. Tab detail reuses the list. Undo on every delete or archive.

4

Review queue + SMS page

Merge the classify banners and sheets with the SMS problem items into To review. Rebuild the Bank SMS page. Fix notification actions.

5

Settings, Import, Onboarding

4 settings groups. One import that only asks about uncertain rows. 3-step onboarding. Ask for permissions in context.

6

Home, widgets, words

Home cards and their states (same order as today). Themed widgets (and fewer of them). Glossary pass into strings.xml.
